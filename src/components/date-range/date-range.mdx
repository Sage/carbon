# Date Range

<a

A date range captures a start date and an end date selected or entered by a user.

It comes in two types, chosen with the `rangeType` prop:

- **Standard** (`rangeType="standard"`, the default) renders two date inputs, each with its own calendar.
  Use it when the start and end dates are far apart.
- **Combined** (`rangeType="combined"`) renders one button, styled as a date input, that opens a single
  calendar in which the user picks the start date and the end date, then presses Apply. Use it when the
  dates are close together, for example within two calendar months. The component does not limit the range.

To let users choose from ranges your product defines, such as financial years or quarters, compose a
[Select](../?path=/docs/select--docs) with a date range. See [Preset pattern](#preset-pattern).

## Quick Start

```javascript
import DateRange from "carbon-react/lib/components/date-range";
import type {
  DateRangeProps,
  CombinedDateRangeProps,
} from "carbon-react/lib/components/date-range";
```

`DateRangeProps` describes the standard range. Use `CombinedDateRangeProps` for the combined range.
In the next major release `DateRangeProps` will cover every range type.

`React.ComponentProps<typeof DateRange>` is a union of the range types, so an `interface` cannot extend it.
Extend `DateRangeProps` or `CombinedDateRangeProps` instead.

## Standard

### Default

<Canvas of={DateRangeStories.DefaultStory} />

The `value` and `onChange` props are required as this component must be controlled. `onChange` is called whenever a
date changes, and each input always shows `value`. Store the new dates in `value` when `onChange` is called, as in the
example above. To reject an edit, keep `value` unchanged and the input shows it again.

For each date, `onChange` provides a `formattedValue` for display and a `rawValue` in ISO format (`YYYY-MM-DD`) for
valid dates. Use `rawValue` when submitting or storing dates; it is `""` for an empty date and `null` for an invalid one.

Use the `required` prop to indicate that the fields are mandatory.

### Legacy prop compatibility

Deprecated props remain in the TypeScript API to avoid a breaking type change, but the following legacy presentation props are not supported by the standard type.

| Deprecated prop         | Behavior      | Replacement                                                                                                                           |
| ----------------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `startInfo` / `endInfo` | Not supported | Use `startDateProps.inputHint` / `endDateProps.inputHint`, `startWarning` / `endWarning`, or `startError` / `endError` as appropriate |
| `tooltipPosition`       | Not supported | Inline `inputHint`, `warning`, or `error` content                                                                                     |
| `validationOnLabel`     | Not supported | Inline `warning` or `error` messages                                                                                                  |

### Sizes

The `size` prop sets the size of both inputs and the space between them. A parent `Fieldset`'s size takes priority.
It applies to both range types: the first three examples are Standard and the last three are Combined.

### Prevent an end date before the start date

Start dates before 1 July 2025 are unavailable. After selecting a start date, earlier dates are unavailable in the
end-date calendar. The two date inputs are otherwise independent, so set `endDateProps.minDate` to the start date's
`rawValue` when `onChange` is called, as in the example below.

### Validation

Validation states are applied to each date input separately, with the `startError`, `endError`, `startWarning` and
`endWarning` props. See our [Validations](../?path=/docs/documentation-validations--docs) documentation page for more information.

By default validation messages render above the inputs. Set `validationMessagePositionTop` to `false` to render them
below the inputs, as in the last example.

## Combined

### Combined default

The button shows the start date followed by "to" once the first date is picked, then the whole range.
Picking a date does not close the calendar. Clear empties the selection and keeps the calendar open.

The dates picked in the calendar are a draft until Apply. Apply closes the calendar and calls `onChange` with the
range, but only if it differs from `value`. With only a start date picked, Apply still closes the calendar and calls
`onChange` with a partial range, where the end date's `rawValue` is `""`. Pressing Esc, clicking outside the calendar
or clicking the button again closes the calendar and discards the draft, without calling `onChange`.

This differs from the standard type, where `onChange` is called whenever a date changes.

A click on a complete range starts a new range. Clicking the start date again completes a one-day range, and a second
date before the start completes the range, with the first date as the end.

<Canvas of={DateRangeStories.Combined} />

### Combined validation

The combined type has one `error` and one `warning` for the whole field. An empty date is valid and is reported as
`{ formattedValue: "", rawValue: "" }`, so a required field must check for empty dates when `onChange` is called or
before the form is submitted. The component shows no error for a partial range; the example below sets `error` when
Apply is pressed with only a start date. A value that is not a valid date, or an end date before the start date, is shown and reported as given,
with `rawValue: null` for an invalid date; show the problem with `error`.

## Preset pattern

A preset date range is not a range type. Build it from a [Select](../?path=/docs/select--docs) of the ranges your
product defines and a date range for Custom range:

- Pass the ranges to `Select` as `Option` elements, optionally under `OptionGroupHeader` headings. To make a prefix
  such as "FY26:" bold in the list, write it in the option's children; `text` is what the field shows.
- Add a Custom range `Option` last, with a value of your choice, and render a date range below the `Select` only while
  it is selected. Use a Combined date range when the dates are close together, or a Standard one when they are far
  apart. Keep its dates in your state, so they are still there if Custom range is chosen again.
- Give both fields the same `size`, or put them in a `Fieldset`, whose size takes priority.
- Validate each field on its own: set `error` on the `Select` when nothing is chosen, and the date range's own error
  props when its dates are missing.
- `Select` with a `name` submits the text of the chosen option. To submit its value, leave `name` off the `Select` and
  add a hidden input holding the value, as in the examples. Name the date range's inputs with its own `name`.

Choosing Custom range closes the list and returns focus to the `Select`. The date range is next in the tab order, so Tab
moves into it.

The examples below are forms. Select a preset or enter a custom range, then choose Submit to validate the fields and
view the submitted values.

## Fieldset and forms

### In a Fieldset

A parent `Fieldset`'s size takes priority over the `size` prop for both range types.

<Canvas of={DateRangeStories.InFieldset} />

### In a Form

When `name` is set, Standard and Combined name their form fields `${name}-start` and `${name}-end`.

- Standard submits the text shown in each input. `startDateProps.name` and `endDateProps.name` take priority.
- Combined renders two hidden inputs holding the ISO date (`YYYY-MM-DD`), or an empty value for an empty or invalid
  date. When `disabled` is set, nothing is submitted. Submitting the form while the calendar is open first restores
  the value it had when it opened, so a range that wasn't applied is never submitted.

## Props passed to the date inputs

The standard type renders two [Date Input](../?path=/docs/date-input--docs) components. Pass any Date Input prop
to them with `startDateProps` and `endDateProps`, for example `allowEmptyValue`, `disabled`, `readOnly`, `minDate`,
`maxDate`, `pickerProps` or `variant`. See the Date Input documentation for how each one works.

The locale, including the `date-fns` locale used by the calendar, comes from the
[I18nProvider](../?path=/docs/documentation-i18n--docs), as for Date Input.
Do not pass a locale through `pickerProps`.

## Accessibility

- **Standard:** each date input is a text field with its own calendar button and its own label, set with `startLabel`
  and `endLabel`. Each calendar dialog is named by its input's label. Only one calendar is open at a time.
- **Combined:** the field is a combobox button named by `label`. Enter or Space opens a calendar dialog, named by the
  same `label`, and moves focus to the start date or, with no value, today.
  Tab moves through the day grid, Clear, Apply and the month and year selects. A status message is announced after
  each date is picked, and Apply returns focus to the button.
