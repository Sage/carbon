# Form

Represents a document section containing interactive controls for submitting information.

## Quick Start

To use Form, import the `Form` and pass the content, usually various inputs, as children.
Compose content as children. Place an error `Message` summary at the top of the form, directly after the form heading
if present, and before the required-fields indicator and fields. Place warning `Message` components before the fields
they relate to.

```javascript
import Form, {
  RequiredFieldsIndicator,
} from "carbon-react/lib/components/form";
```

## Examples

### Form composition

Start the form with its heading and the `RequiredFieldsIndicator`. Give each section a heading and separate the
sections with a horizontal `Divider`. Place the buttons last, ordered from lowest to highest emphasis.

For the error pattern, with the summary linked to the invalid fields, see [Validations](#validations).

### Spacing between content blocks

Form does not set the gap between its content blocks. Set it on each block with a margin prop:

- between blocks, such as headings, messages, sections and `Divider`s: `--global-space-layout-xs`, for example
  `mb="var(--global-space-layout-xs)"`
- between fields in a section: `--global-space-comp-l`
- between buttons: `--global-space-comp-m`

Use a `Fieldset` only to group inputs that belong together, such as the parts of a name or an address. It sets the
gap between its legend and its inputs, and between the inputs.

While the deprecated `fieldSpacing` prop keeps its default, Form still adds a bottom margin to each field and
`Fieldset`. A margin prop on the block overrides it.

### Validations

Form does not collect validation errors or warnings. Compose them with the following pattern:

1. Set the `error` prop on each invalid field, so its message is shown next to the field and associated with it.
2. Render an error `Message` at the top of the form, directly after the form heading if present and before the
   required-fields indicator and fields. List each problem as a `Link` that moves focus to the field it describes. Each
   link must match its inline error message exactly and must not end with a full stop.
3. After a submit attempt that fails validation, move focus to the first summary `Link` by passing it a `ref`. This
   announces the summary to screen reader users. Do not also place it in a live region, or it is announced twice.
4. Render warning `Message` components without moving focus, because warnings do not block submission.

Remove the summary once the errors are fixed.

Do not combine a composed summary with the deprecated `errorCount` or `warningCount` props. Form still renders their
counts in the footer, so the errors and warnings would be summarised twice.

### Required Fields Indicator

The `RequiredFieldsIndicator` component visually indicates that form fields are required using an asterisk prefix. It can be used
within a `Form` to provide users with a clear indication of which fields are mandatory, or used independently.

<Canvas of={FormStories.RequiredFieldsIndicatorStory} />

The `RequiredFieldsIndicator` component can be rendered without children to display a custom message or style, while still maintaining the asterisk.
This allows for flexibility in how required fields are communicated to users in different locales.

The asterisk can sit at the start of the text, in the middle of a sentence or at the end, and the text can wrap
onto several lines. To place it inside a sentence, render `RequiredFieldsIndicator` without children and with
`as="span"`. The asterisk adds its own space after it, so leave out the space between the indicator and the next word.

Do not name the symbol next to the indicator, for example "An asterisk \* indicates required information". Screen
readers announce the asterisk itself, so the symbol is read twice. Write "Fields marked \* are required" instead.

<Canvas of={FormStories.CustomRequiredFieldsIndicatorStory} />

## Translation keys

The following keys are available to override the translations for this component by passing in a custom locale object to the
[i18nProvider](../?path=/docs/documentation-i18n--docs).

They apply only to the summary rendered by the deprecated `errorCount` and `warningCount` props. A composed `Message`
summary has no translation keys; provide its text through your application's own translations.
