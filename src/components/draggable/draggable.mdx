# Draggable

Pick, move and replace an order. Draggable is a great component if you need to have interactive components
with possibility to change their order with drag and drop mechanics

## Quick Start

To use the Draggable component you have to import two components: `<DraggableContainer />` and `<DraggableItem />`.

```javascript
import {
  DraggableContainer,
  DraggableItem,
} from "carbon-react/lib/components/draggable";
```

- Always use `DraggableItem` inside of the `DraggableContainer`
- `DraggableItem` doesn't work without `DraggableContainer`
- `DraggableItem` requires an `id` that is unique within its `DraggableContainer`.
- Drag an item using its drag handle. Its content remains interactive.
- The ghost placeholder matches the registered surface's size and corners in Card, Tile, and integrated custom components.
- Items stay in their original position while dragging. The destination line appears on the left or right when moving within a visual row, and above or below when moving between rows. Its ends are inset to avoid rounded corners. Dropping still moves the item to the target's position in the ordered list.
- Dropping outside the container leaves the order unchanged.

### With Cards and Tiles

Pass the parent component as a child of `DraggableContainer`, then wrap each draggable child in `DraggableItem`:

```tsx
<DraggableContainer getOrder={handleOrderChange}>
  <Box display="flex" flexDirection="column" gap={2}>
    <DraggableItem id="card">
      <Card width="100%" m={0}>
        Card content
      </Card>
    </DraggableItem>
    <DraggableItem id="tile">
      <Tile>Tile content</Tile>
    </DraggableItem>
  </Box>
</DraggableContainer>
```

The parent keeps its own props and layout. Its children must be `DraggableItem` components. You can also continue passing items directly to `DraggableContainer`.

`DraggableItem` enables Card and Tile's draggable presentation through context and uses their built-in handles. You do not need to set Card's `draggable` prop, and Tile does not have a `draggable` prop. Components without an integrated handle receive a fallback handle. Child components do not need to forward refs.

### Integrating a custom component

Use `useDraggableItemContext` and `DragHandle` from the public draggable entry point. Card and Tile use this same integration:

```tsx
import {
  DragHandle,
  useDraggableItemContext,
} from "carbon-react/lib/components/draggable";

function CustomPanel({ children }) {
  const { isDraggable, surfaceRef } = useDraggableItemContext();

  return (
    <article ref={surfaceRef} style={{ borderRadius: "16px" }}>
      {isDraggable && <DragHandle />}
      {children}
    </article>
  );
}
```

Attach `surfaceRef` to the outer HTML element whose bounds and corners should be used while dragging, and render one `DragHandle` inside it. The handle registers itself and replaces the fallback handle. The component does not need to forward a ref or accept a `draggable` prop. The hook returns `isDraggable: false` outside a `DraggableItem`, so the same component works independently.

`DragHandle` accepts span attributes and a forwarded ref. It provides pointer dragging; provide separate accessible controls for manually reordering items, as shown in the Card and Tile stories using `rightChildren`.

#### Custom elements and components

This example uses a plain HTML grid inside a custom parent component, with six custom panels rendered as articles or sections. The panels use the public hook and handle to place their handles inside their bounds. Click the counters, then reorder their components to check that local state is preserved.

Without an integrated handle, the ghost and indicator use the DraggableItem wrapper's bounds and corners. The integrated panels register their own surfaces, so their ghost, native drag preview, and indicator match their bounds and corners, including square corners.

## Accessibility

Always provide keyboard and click/tap controls alongside pointer dragging. `DragHandle` is pointer-only and its icon is hidden from assistive technology. It does not implement keyboard dragging.

Controls rendered inside a `DraggableItem` can use the public hook to move their item:

```tsx
function ReorderControls() {
  const { index, itemCount, moveTo } = useDraggableItemContext();
  return (
    <>
      <button disabled={index === 0} onClick={() => moveTo(index - 1)}>
        Move earlier
      </button>
      <button
        disabled={index === itemCount - 1}
        onClick={() => moveTo(index + 1)}
      >
        Move later
      </button>
    </>
  );
}

<DraggableContainer getOrder={handleOrderChange}>
  <DraggableItem id="report">
    <Card rightChildren={<ReorderControls />}>Quarterly report</Card>
  </DraggableItem>
</DraggableContainer>;
```

`index` and `moveTo` use zero-based positions. Invalid positions and moves to the current position are ignored. Outside a `DraggableItem`, the hook returns an item count of zero and `moveTo` does nothing.

Both dragging and `moveTo` update the same order and call `getOrder`. Draggable does not create a live region or generate announcements. Consumers should use this callback to update their own status region, coordinating messages with the rest of their page and providing their own readable item names and translations.

For example, keep a visually hidden status region mounted from the initial render and update its text after a successful reorder:

```tsx
function ReorderableReports() {
  const [announcement, setAnnouncement] = React.useState("");
  const labels = { quarterly: "Quarterly report", annual: "Annual report" };

  const handleOrder = (ids, movedId) => {
    const position = ids.indexOf(movedId) + 1;
    setAnnouncement(
      `${labels[movedId]} moved to position ${position} of ${ids.length}.`,
    );
  };

  return (
    <>
      <DraggableContainer getOrder={handleOrder}>
        {Object.entries(labels).map(([id, label]) => (
          <DraggableItem key={id} id={id}>
            <Card rightChildren={<ReorderControls />}>{label}</Card>
          </DraggableItem>
        ))}
      </DraggableContainer>
      <Typography
        as="div"
        screenReaderOnly
        role="status"
        aria-live="polite"
        aria-atomic="true"
      >
        {announcement}
      </Typography>
    </>
  );
}
```

The stories include a consumer-owned announcement wrapper, using two alternating status regions so consecutive identical messages can also be announced. You can instead integrate `getOrder` with an existing announcement service on your page.

Manual moves restore focus to the control that initiated the move, provided it remains mounted and focusable. ActionPopover returns focus to its trigger before calling an action, and DraggableContainer restores that trigger's focus after moving the item. Give each menu trigger an item-specific accessible name, as in the stories. If a custom control becomes disabled or unmounts after moving, provide a suitable focus destination yourself. If you reorder by changing children directly instead of calling `moveTo`, provide your own announcement and focus management.

The stories demonstrate ActionPopover controls for Cards, Tiles, custom panels, and fallback-handle items. Test the full interaction with a keyboard and screen reader as well as automated accessibility checks.

## Testing drag behaviour

### Recommended approach

We recommend testing drag and drop interactions in browser environments using Playwright, rather than Node-based environments like JSDOM. Since JSDOM does not render visual content, tests will require extensive mocking to simulate drag and drop behaviour, making them less effective.

### JSDOM tests (if required)

For JSDOM tests, install `@atlaskit/pragmatic-drag-and-drop-unit-testing` and import its `drag-event-polyfill` in your test setup. Mock `document.elementsFromPoint` to return the drag handle, then start the drag on that handle:

```tsx
const handle = screen.getAllByTestId("draggable-item-drag-handle")[0];
const target = screen.getByTestId("target-item");

Object.defineProperty(document, "elementsFromPoint", {
  configurable: true,
  value: jest.fn(() => [handle]),
});

fireEvent.dragStart(handle);
fireEvent.dragEnter(target);
fireEvent.dragOver(target);
fireEvent.drop(target);
fireEvent.dragEnd(handle);
```

This example assumes `getByTestId` is configured to use `data-role`, and the destination item has `data-role="target-item"`. Reordering uses the item order; use browser tests to verify indicator direction and surface geometry.
