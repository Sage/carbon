# Data Grid

<a
  target="_blank"
  href="https://designsystem.sage.com/fusion/latest/pages/components/data-grid/"

  Product Design System component
</a>

Data Grid is an editable, spreadsheet-like pattern for capturing and managing
line-item data. Use [Table](?path=/docs/table--docs) when users only need to
compare or read data.

The component has one fixed `medium` size and a subtle header. Its API is
data-driven: provide an array of row objects and an array of column definitions.
The row, header, cell, layout, keyboard, editing, and virtualization building
blocks are private implementation details.

## Quick Start

```tsx
import {
  DataGrid,
  DataGridColumn,
} from "carbon-react/lib/components/data-grid";

const columns: DataGridColumn<InvoiceLine>[] = [
  {
    field: "description",
    headerName: "Description",
  },
  {
    field: "category",
    headerName: "Category",
    type: "dropdown",
    options: [
      { label: "Services", value: "services" },
      { label: "Software", value: "software" },
    ],
  },
  {
    field: "selected",
    headerName: "Selected",
    type: "checkbox",
  },
];

<DataGrid
  aria-label="Invoice lines"
  rows={rows}
  columns={columns}
  onRowsChange={(nextRows) => setRows(nextRows)}
/>;
```

## Data model

Data Grid does not own or mutate application data. Two inputs describe the
grid:

1. `rows` contains the values and remains the application's source of truth.
2. `columns` maps row fields to cell behaviour, layout, and presentation.

Type both with the same row interface. This gives field-name autocomplete and
narrows properties such as `options` and `renderCell` to the cell types that
support them.

### Define the rows

Each row should have a stable identifier. Data Grid reads `row.id` by default;
use `getRowId`, for example `getRowId={(row) => row.lineId}`, when the row type
uses a different property.

```tsx
interface InvoiceLine {
  id: number;
  description: string;
  category: "Services" | "Software" | "Expenses";
  selected: boolean;
  locked: boolean;
}

const initialRows: InvoiceLine[] = [
  {
    id: 1,
    description: "Consulting services",
    category: "Services",
    selected: false,
    locked: false,
  },
];
```

### Define the columns

Every column needs a unique `field` and a visible `headerName`. Editable text,
dropdown, and checkbox fields must name a property on the row so emitted data
retains the supplied schema. Action columns may use a synthetic field because
they never write a value. Text is the default cell type, while the other types
add their own required configuration.

| Cell type | Configuration                      | Intended use                                             |
| --------- | ---------------------------------- | -------------------------------------------------------- |
| Text      | Omit `type`, or use `type: "text"` | Editable text and numeric-looking values                 |
| Dropdown  | `type: "dropdown"` and `options`   | A value chosen from a fixed list                         |
| Checkbox  | `type: "checkbox"`                 | The selectable-row checkbox in the current specification |
| Action    | `type: "action"` and `renderCell`  | An action popover or equivalent contextual control       |

```tsx
const columns: DataGridColumn<InvoiceLine>[] = [
  {
    field: "description",
    headerName: "Description",
    minWidth: 220,
    flex: 1,
    error: ({ value }) =>
      String(value ?? "").trim() ? false : "Enter a description",
    readOnly: ({ row }) => row.locked,
  },
  {
    field: "category",
    headerName: "Category",
    type: "dropdown",
    width: 180,
    options: [
      { label: "Services", value: "Services" },
      { label: "Software", value: "Software" },
      { label: "Expenses", value: "Expenses" },
    ],
  },
  {
    field: "selected",
    headerName: "Selected",
    type: "checkbox",
    width: 100,
  },
  {
    field: "actions",
    headerName: "",
    headerAriaLabel: "Actions",
    type: "action",
    width: 52,
    renderCell: ({ api, row, rowId }) => (
      <ActionPopover
        aria-label={`Actions for ${row.description}`}
        buttonLabel="More actions"
      >
        <ActionPopoverItem
          onClick={() =>
            api.duplicateRow(rowId, { ...row, id: createInvoiceLineId() })
          }
        >
          Duplicate
        </ActionPopoverItem>
        <ActionPopoverItem onClick={() => api.deleteRow(rowId)}>
          Delete
        </ActionPopoverItem>
      </ActionPopover>
    ),
  },
];
```

Shared column properties configure the cells without changing the row data:

| Concern          | Properties                                     |
| ---------------- | ---------------------------------------------- |
| Sizing           | `width`, or `flex` with an optional `minWidth` |
| Position         | `sticky: "left"` or `sticky: "right"`          |
| Content          | `align`, `weight`, `headerAriaLabel`           |
| State            | `readOnly`, `error`                            |
| Custom rendering | `renderCell`                                   |

`readOnly`, `error`, and `renderCell` receive the same cell parameters:
`row`, `rowId`, `field`, `value`, `column`, and the row-operation `api`. Use
fixed values when every row behaves the same way, or functions when behaviour
depends on row data.

### Receive updated rows

Data Grid is controlled: it never mutates `rows`. A committed text edit,
dropdown choice, or checkbox toggle creates a new row collection and passes it
to `onRowsChange`. Store that collection and pass it back to Data Grid.

```tsx
const [rows, setRows] = React.useState(initialRows);

const handleRowsChange = (
  nextRows: InvoiceLine[],
  change: DataGridRowChange<InvoiceLine>,
) => {
  setRows(nextRows);
  auditInvoiceChange(change);
};

<DataGrid
  aria-label="Invoice lines"
  rows={rows}
  columns={columns}
  onRowsChange={handleRowsChange}
/>;
```

The second argument is a discriminated change object. Its `type` identifies a
`cell-edit`, `dropdown-select`, `checkbox-toggle`, `row-add`, `row-insert`,
`row-duplicate`, `row-delete`, or `row-move` transaction. Cell transactions
include previous and next values and rows; structural transactions include the
affected stable row ID and indexes where relevant. Unchanged edits do not emit
`onRowsChange`.

The example below shows both values emitted by the component. Edit a cell, add
a row, or use a row action to inspect the updated row array and its most recent
change transaction.

### Add, insert, duplicate, delete, and move rows

Custom action cells receive the row API through `renderCell`. Buttons outside
the grid can use the same API through the forwarded ref. Consumers create the
row—including its unique ID and business defaults—while Data Grid applies the
operation and emits `onRowsChange`.

```tsx
const gridRef = React.useRef<DataGridHandle<InvoiceLine>>(null);

<Button onClick={() => gridRef.current?.addRow(createEmptyInvoiceLine())}>
  Add line
</Button>;

gridRef.current?.insertRow(newLine, { beforeRowId: existingLineId });
gridRef.current?.duplicateRow(sourceLineId, duplicatedLine);
gridRef.current?.deleteRow(lineId);
gridRef.current?.moveRow(lineId, 3);
```

`moveRow` receives the row's final zero-based index. `insertRow` accepts an
absolute index, `beforeRowId`, or `afterRowId`. Operations with an unknown row
ID do not emit a change. Adding or inserting a row whose ID already exists
throws a developer-facing error, because unique stable IDs are required for
focus, virtualization, and row operations.

### Validate business data

Data Grid preserves the consumer's row shape and enforces editable fields at
the TypeScript boundary. Products remain responsible for domain rules such as
required descriptions, permitted categories, generated IDs, and API payload
conversion. Validate `nextRows` with the product's existing schema library
(for example Yup, Zod, or JSON Schema) before saving when required.

Row selection is being separated from ordinary Boolean checkbox data. The
intended API will make selection an explicit opt-in rather than inferring it
from the first checkbox column.

## Examples

### Cell types and states

The four supported cell types are text, dropdown, checkbox, and action. Text is
the default, so its `type` can be omitted. Use `weight="medium"` to give
non-editing content additional emphasis; editors always use regular weight.

This example also includes an empty cell with an error and a read-only row.
Hover a cell, navigate with the arrow keys, and press **Enter** to compare the
resting, hover, navigation-focus, and active-edit treatments. Checkboxes toggle
with one click or **Space**.

<Canvas of={DataGridStories.EditableInvoiceLines} />

Use `readOnly` and `error` as either fixed values or functions when the state
depends on a row. Checkbox and action columns intentionally do not accept
errors. Action cells receive custom content through `renderCell`; the content
should use the keyboard behavior of its underlying component.

### Sticky columns and optional header

Columns are not sticky by default: neither their position nor the action cell
type pins them. Opt in by setting `sticky="left"` or `sticky="right"` on the
relevant column definition. In this example, the line number and action columns
stay visible while the editable columns scroll beneath them. The header remains
visible because this example also opts in with `stickyHeader`; headers scroll
with the grid by default.

<Canvas of={DataGridStories.StickyColumns} />

Scrolling cells are transparent so the grid can sit naturally on its containing
surface. Sticky cells require an opaque surface to prevent scrolling content
showing through. They use `--table-row-bg-default` by default; set
`--data-grid-sticky-cell-bg` on a containing element when the grid sits on a
different surface.

### Validation and error summaries

Set `error` on a text or dropdown column to add both the visual error treatment
and an accessible description. Use the forwarded ref to connect an error
summary to a cell. `focusCell` moves navigation focus to the cell; `editCell`
activates its editor and focuses it in one operation.

<Canvas of={DataGridStories.ValidationAndErrorSummary} />

```tsx
const gridRef = React.createRef<DataGridHandle<InvoiceLine>>();

gridRef.current?.editCell(invoiceLineId, "description");
```

### Large data sets

Set `maxHeight` to create an internal vertical scroll area. Data Grid
automatically virtualizes rows when the constrained grid contains more than 20
rows. `rowOverscan` controls how many additional rows remain mounted above and
below the viewport. Use `disableVirtualization` only when a specialist
integration requires every row to remain in the DOM.

Columns remain mounted so sticky positioning, editing, accessible column
relationships, and horizontal keyboard navigation remain predictable.

## Keyboard behavior

Data Grid has separate navigation and edit modes:

- Arrow keys move between cells.
- **Enter** edits text and dropdown cells, or opens an action cell.
- **Space** opens a focused dropdown or toggles a focused checkbox.
- Typing on a text cell starts editing, preserves its value, and appends the
  typed character.
- **Escape** cancels an edit and returns to navigation mode.
- Set `enableTabNavigation` to move through cells with **Tab** and
  **Shift+Tab**. In edit mode, Tab commits the value before moving.

Navigation focus uses the single, high-contrast focus border. Edit mode uses
Carbon's dual inset focus treatment to distinguish an active editor from the
cell being navigated. Text editors place the caret at the end of the existing
value; dropdowns open when the browser supports programmatic picker opening.

## Accessibility

Data Grid uses `div` elements with ARIA grid roles rather than native table
elements. This supports a single roving tab stop and separate navigation and
edit modes while still exposing grid, row, column-header, and grid-cell
semantics to assistive technology.

Provide either `aria-label` or `aria-labelledby`. Use `aria-describedby` for
additional keyboard guidance or an error summary. A drag handle is not yet in
scope; when added, it must be skipped by keyboard navigation and hidden from
screen readers as described by the design specification.
