## Quick Start

Provide an array of row objects and a column definition for each value displayed
in the grid. Data Grid is controlled. Store the rows received by `onRowsChange`
and pass them back to the component.

```tsx
import React from "react";
import {
  DataGrid,
  DataGridColumn,
} from "carbon-react/lib/components/data-grid";

interface InvoiceLine {
  id: number;
  description: string;
  category: "Services" | "Software";
}

const columns: DataGridColumn<InvoiceLine>[] = [
  {
    field: "description",
    headerName: "Description",
  },
  {
    field: "category",
    headerName: "Category",
    type: "dropdown",
    options: [
      { label: "Services", value: "Services" },
      { label: "Software", value: "Software" },
    ],
  },
];

export default function InvoiceLines() {
  const [rows, setRows] = React.useState<InvoiceLine[]>([
    { id: 1, description: "Consulting", category: "Services" },
  ]);

  return (
    <DataGrid
      aria-label="Invoice lines"
      rows={rows}
      columns={columns}
      onRowsChange={(nextRows) => setRows(nextRows)}
    />
  );
}
```

Each row requires a stable ID. Data Grid reads the `id` property by default.
Use `getRowId` when your row uses a different property.

See the [Data and API guide](?path=/docs/data-grid-data-and-api-guide--docs) for
detailed row and column definitions, change events, validation, and row
operations.

## Examples

### Cell types and states

Data Grid supports text, dropdown, checkbox, and action cells. Text is the
default cell type, so its `type` can be omitted. Use `weight: "medium"` to give
cell content additional emphasis when it is not being edited.

This example includes an empty cell with an error and a read-only row. Click or
tap an editable text or dropdown cell once to open its editor. When a cell has
navigation focus, use the arrow keys to move between cells and press **Enter**
to edit. Checkboxes toggle with one click or **Space**. **Space** also opens a
focused dropdown or action popover.

<Canvas of={DataGridStories.EditableInvoiceLines} />

Use `readOnly` and `error` as fixed values or functions when the state depends
on row data. Checkbox and action columns do not support the error state. Action
cells use `renderCell` to display controls such as an action popover.

Read-only dropdown cells display their selected label as text, and read-only
checkboxes cannot be changed. Action controls remain available because they do
not edit the cell value. Disable individual actions in `renderCell` when the
product's business rules require it. Clicking another cell dismisses an open
action popover and moves focus to the clicked cell or its editor. Keyboard
dismissal still returns focus to the action trigger.

### Pinned columns and optional sticky header

Columns are not pinned by default. Set `pinned: "left"` or `pinned: "right"`
on the relevant column definition. Pinned columns should form contiguous groups
at the corresponding edge and use predictable widths. In this example, the
line number and action columns remain visible while the other columns scroll
beneath them.

Set `stickyHeader` to keep the header visible while the grid scrolls vertically.
Headers scroll with the grid by default.

<Canvas of={DataGridStories.PinnedColumns} />

Body cells use the opaque `--table-row-bg-default` surface. Non-sticky headers
use `--table-header-subtle-bg-default` so they blend into their containing
surface. Pinned columns and sticky headers use the opaque row surface to stop
scrolling content from showing through.

### Validation and error summaries

Set `error` on a text or dropdown column to display an error and provide an
accessible description for both the cell and its editor. Error-summary layout
is owned by the consuming application. Use `aria-describedby` to associate the
grid with external summary or guidance content, and use the forwarded ref to
connect each summary link to a cell. `focusCell` moves navigation focus to the
cell. `editCell` opens the editor and moves focus to it.

<Canvas of={DataGridStories.ValidationAndErrorSummary} />

```tsx
const gridRef = React.createRef<DataGridHandle<InvoiceLine>>();

gridRef.current?.editCell(invoiceLineId, "description");
```

### Large data sets

Set `maxHeight` to create a vertical scroll area. Data Grid automatically
virtualizes rows when a constrained grid contains more than 20 rows.
`rowOverscan` controls how many additional rows remain mounted above and below
the visible rows.

Use `disableVirtualization` only when an integration requires every row to
remain in the DOM. Columns remain mounted so horizontal keyboard navigation,
editing, and pinned positioning remain predictable.

## Keyboard behavior

Data Grid follows the
[WAI-ARIA Grid Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/grid/).
The `grid`, `row`, `columnheader`, and `gridcell` roles expose the tabular
structure to assistive technologies. ARIA roles do not add keyboard behaviour
by themselves; Data Grid implements the supported interactions listed below.

Data Grid has separate navigation and edit modes:

- Arrow keys move between cells.
- **Home** and **End** move to the first or last cell in the current row.
- **Ctrl+Home** and **Ctrl+End** move to the first or last cell in the grid.
- **Enter** edits text and dropdown cells, or opens an action cell.
- **Space** opens a focused dropdown or action popover, or toggles a focused
  checkbox.
- Typing on a text cell starts editing and appends the typed character to its
  current value.
- **Escape** cancels an edit and returns to navigation mode.
- Set `enableTabNavigation` to move through cells with **Tab** and
  **Shift+Tab**. In edit mode, Tab commits the value before moving. Tab from
  the last cell and Shift+Tab from the first cell leave the grid.

Navigation focus uses a single high-contrast border. Edit mode uses Carbon's
dual inset focus treatment. Text editors place the cursor at the end of the
current value. Dropdown cells use Carbon Select. Opening a dropdown moves focus
to the Select and displays its options for keyboard or pointer selection.

Scrolling does not save an edit. If virtualisation removes a text editor from
view, its draft and selection are kept so the user can continue editing or
cancel when they return.

## Accessibility

Data Grid uses ARIA grid semantics and a single roving tab stop. Navigation and
edit modes allow users to move through cells before entering interactive
content.

Editable text cells open on a single click or tap, including click activation
generated by assistive technologies. No touch or screen-reader detection is
required. Verify editing, focus, and software-keyboard behaviour with VoiceOver
on iOS and TalkBack on Android; browser touch emulation does not reproduce those
interactions.

Built-in checkbox cells expose a full-cell checkbox target with its accessible
name, checked state, and read-only state. The checkbox graphic is decorative;
the cell handles toggling. A click or tap anywhere in an action cell opens its
first interactive control, just as Enter or Space does. This includes
assistive-technology click activation, regardless of click count or preceding
pointer events.
Direct activation of a nested action control still uses that control's own
behaviour. Actions remain available in read-only rows.

When testing with VoiceOver on macOS, interact with the grid and use VoiceOver
commands such as **Control+Option+Arrow keys** to inspect its semantic structure
and hear row and column context. Unmodified arrow keys operate Data Grid's focus
navigation after a cell has focus. Other screen readers provide their own
equivalent commands for navigating interactive grids.

Provide either `aria-label` or `aria-labelledby`. Use `aria-describedby` for
additional keyboard guidance or an error summary. Custom controls supplied to
action cells must provide their own accessible names and keyboard behaviour.
