## Define rows

Data Grid does not own or mutate application data. The `rows` array remains the
application's source of truth.

Type the rows and columns with the same interface. This provides field-name
autocomplete and checks that editable columns refer to properties on the row.

Each row requires a stable, unique identifier. Data Grid reads the `id`
property by default. Use `getRowId`, for example
`getRowId={(row) => row.lineId}`, when the row uses a different property.

```tsx
interface InvoiceLine {
  id: number;
  description: string;
  category: "Services" | "Software" | "Expenses";
  included: boolean;
}

const initialRows: InvoiceLine[] = [
  {
    id: 1,
    description: "Consulting services",
    category: "Services",
    included: false,
  },
];
```

## Define columns

Every column requires a unique `field` and a visible `headerName`. Use
`headerAriaLabel` when the visible heading is intentionally empty.

Text, dropdown, and checkbox fields must refer to a property on the row. Action
columns may use a field that is not present on the row.

| Cell type | Configuration                      | Use                                        |
| --------- | ---------------------------------- | ------------------------------------------ |
| Text      | Omit `type`, or use `type: "text"` | Edit text and numeric-looking values       |
| Dropdown  | `type: "dropdown"` and `options`   | Select a value from a fixed list           |
| Checkbox  | `type: "checkbox"`                 | Toggle a Boolean value                     |
| Action    | `type: "action"` and `renderCell`  | Display an action popover or other control |

```tsx
const columns: DataGridColumn<InvoiceLine>[] = [
  {
    field: "description",
    headerName: "Description",
    minWidth: 220,
    flex: 1,
    readOnly: true,
  },
  {
    field: "category",
    headerName: "Category",
    type: "dropdown",
    width: 180,
    options: [
      { label: "Services", value: "Services" },
      { label: "Software", value: "Software" },
      { label: "Expenses", value: "Expenses" },
    ],
  },
  {
    field: "included",
    headerName: "Included",
    type: "checkbox",
    width: 100,
  },
  {
    field: "actions",
    headerName: "",
    headerAriaLabel: "Actions",
    type: "action",
    width: 52,
    renderCell: ({ api, row, rowId }) => (
      <ActionPopover
        aria-label={`Actions for ${row.description}`}
        renderButton={({ "data-element": dataElement, ariaAttributes }) => (
          <Button
            data-element={dataElement}
            size="small"
            variant="default"
            variantType="subtle"
            {...ariaAttributes}
          >
            <Icon type="ellipsis_vertical" />
          </Button>
        )}
        size="medium"
      >
        <ActionPopoverItem
          onClick={() =>
            api.duplicateRow(rowId, { ...row, id: createInvoiceLineId() })
          }
        >
          Duplicate
        </ActionPopoverItem>
        <ActionPopoverItem onClick={() => api.deleteRow(rowId)}>
          Delete
        </ActionPopoverItem>
      </ActionPopover>
    ),
  },
];
```

`createInvoiceLineId` is supplied by your application and must return a unique
ID for each duplicated row.

### Column properties

| Purpose          | Properties                                     |
| ---------------- | ---------------------------------------------- |
| Sizing           | `width`, or `flex` with an optional `minWidth` |
| Position         | `pinned: "left"` or `pinned: "right"`          |
| Content          | `align`, `weight`, `headerAriaLabel`           |
| State            | `readOnly`                                     |
| Custom rendering | `renderCell`                                   |

Set `width` for a fixed pixel width. Use `flex` to share the available space
between flexible columns, with `minWidth` as the lower limit. Columns without
sizing use the default width, while action columns use their compact default.

The `renderCell` callback receives the current `row`, `rowId`,
`field`, `value`, and `column`. It also receives the row-operation `api`.

Set `readOnly: true` on the column definition to make its values non-editable.

## Receive updated rows

A committed text edit, dropdown selection, or checkbox toggle creates a new row
array and passes it to `onRowsChange`. Store the new array and pass it back to
Data Grid.

```tsx
const [rows, setRows] = React.useState(initialRows);

const handleRowsChange = (
  nextRows: InvoiceLine[],
  change: DataGridRowChange<InvoiceLine>,
) => {
  setRows(nextRows);
  auditInvoiceChange(change);
};

<DataGrid
  aria-label="Invoice lines"
  rows={rows}
  columns={columns}
  onRowsChange={handleRowsChange}
/>;
```

`auditInvoiceChange` is an optional application-provided function for recording
changes. If you only need to update local state, use `onRowsChange={setRows}`.

Changes made before the parent updates `rows` are combined. Pass the array from
`onRowsChange` back as `rows` to accept them. Passing a different array replaces
pending changes.

To discard changes, pass a new copy of the rows you want to keep. Ignoring the
callback or keeping the same array does not discard changes.

The optional second argument describes the change that produced the array. Its
`type` is one of:

- `cell-edit`
- `dropdown-select`
- `checkbox-toggle`
- `row-add`
- `row-insert`
- `row-duplicate`
- `row-delete`
- `row-move`

Cell changes include the previous and next value and row. Structural changes
include the affected row and indexes where relevant. Data Grid does not call
`onRowsChange` when a committed value has not changed.

Use `onBeforeRowChange` to apply application rules, such as calculated totals,
before the grid notifies `onRowsChange`.

## Save or export data

Your application already holds the grid's committed data in `rows`. Use that
state to save changes to your backend or generate an export, such as a PDF.
Only committed edits are included; text still being edited is not yet in `rows`.

### Save on an action

Update local state when rows change, then use that state when the user chooses
to save or export.

<details>
<summary>View example: save or export on a button action</summary>

```tsx
const [rows, setRows] = React.useState(initialRows);

<>
  <DataGrid
    aria-label="Invoice lines"
    rows={rows}
    columns={columns}
    onRowsChange={setRows}
  />
  <Button onClick={() => saveInvoice(rows)}>Save</Button>
  <Button onClick={() => createInvoicePdf(rows)}>Export PDF</Button>
</>;
```

`saveInvoice` and `createInvoicePdf` are functions supplied by your application.

</details>

### Save as data changes

To save without a separate button, update local state and validate the rows
received by `onRowsChange` before saving them.

<details>
<summary>View example: save as data changes</summary>

```tsx
const [rows, setRows] = React.useState(initialRows);

<DataGrid
  aria-label="Invoice lines"
  rows={rows}
  columns={columns}
  onRowsChange={(nextRows) => {
    setRows(nextRows);

    if (isValid(nextRows)) {
      saveInvoice(nextRows);
    }
  }}
/>;
```

`isValid` and `saveInvoice` are functions supplied by your application. Use
`nextRows` for validation and saving because `rows` does not update immediately
after `setRows`.

</details>

Your application handles save timing and failures; Data Grid does not wait for
the save to finish.

## Intercept changes

The optional `onBeforeRowChange` callback runs before each cell edit or row
operation, including operations called through the ref. It receives
`previousRows`, `proposedRows`, and the original `change` details. `previousRows`
includes earlier approved changes waiting for the parent to update `rows`, so
you can compare the latest values with the proposal.

- Return nothing to approve the proposal unchanged.
- Return `false` to discard this operation without calling `onRowsChange`.
- Return a new row array to approve transformed values, such as normalised text
  or calculated totals.

Treat the supplied arrays and row objects as immutable. Transformed rows must
keep the proposed row IDs, membership, and order. To prevent a structural
operation, return `false` rather than returning an earlier row array.

<details>
<summary>View example: trim descriptions and prevent deleting the last row</summary>

```tsx
<DataGrid
  aria-label="Invoice lines"
  rows={rows}
  columns={columns}
  onBeforeRowChange={({ previousRows, proposedRows, change }) => {
    if (change.type === "row-delete" && previousRows.length === 1) {
      return false;
    }
    return proposedRows.map((row) => ({
      ...row,
      description: row.description.trim(),
    }));
  }}
  onRowsChange={(nextRows) => setRows(nextRows)}
/>
```

</details>

`onRowsChange` receives the approved rows, but its `change` argument still
describes the original request, before any transformation.

Interception is synchronous; promises are not supported. Discarding an edit
does not keep its editor open or change normal keyboard navigation. Incoming
`rows` updates and operations that make no change do not trigger interception.

## Row operations

Action cells receive the row API through `renderCell`. Controls outside the
grid can use the same API through the forwarded ref. The consuming application
creates each row, including its unique ID and default values. Each operation
passes through `onBeforeRowChange`, when supplied, before calling `onRowsChange`.

<details>
<summary>View examples: add and manage rows using a ref</summary>

Attach the ref to Data Grid, then call its methods from your controls.

```tsx
const [rows, setRows] = React.useState(initialRows);
const gridRef = React.useRef<DataGridHandle<InvoiceLine>>(null);

<>
  <DataGrid
    ref={gridRef}
    aria-label="Invoice lines"
    rows={rows}
    columns={columns}
    onRowsChange={setRows}
  />
  <Button onClick={() => gridRef.current?.addRow(createEmptyInvoiceLine())}>
    Add line
  </Button>
</>;
```

`createEmptyInvoiceLine` is supplied by your application. It must return a row
with a unique ID and default values for each field.

Other controls can call these methods from their event handlers. Supply your
own row objects and IDs:

```tsx
gridRef.current?.insertRow(newLine, { beforeRowId: existingLineId });
gridRef.current?.duplicateRow(sourceLineId, duplicatedLine);
gridRef.current?.deleteRow(lineId);
gridRef.current?.moveRow(lineId, 3);
```

</details>

`moveRow` receives the final zero-based index. `insertRow` accepts an absolute
index, `beforeRowId`, or `afterRowId`. An operation with an unknown row ID does
not produce a change.

After `addRow`, `insertRow`, or `duplicateRow`, focus moves to the first cell in
the new row. After `deleteRow`, focus moves to the first cell in the following
row, or the previous row when the deleted row was last. This focus recovery
applies when the updated rows are passed back through `onRowsChange`.
Applications using their own row mutation controls should restore focus after
removing the focused element.

Adding, inserting, or duplicating a row with an ID already in the grid throws
an error.

## Validation

Pass an array of `DataGridCellError` objects to `errors` to mark text or dropdown
cells as invalid. Your application controls validation and saving; errors do not
prevent editing, navigation, or saving. Check your application's validation rules
before calling its save function.

<details>
<summary>View example: mark missing descriptions as invalid</summary>

```tsx
const errors: DataGridCellError[] = rows
  .filter((row) => !row.description.trim())
  .map((row) => ({
    rowId: row.id,
    field: "description",
    code: "required",
    message: "Enter a description",
  }));

<DataGrid
  aria-label="Invoice lines"
  rows={rows}
  columns={columns}
  errors={errors}
  onRowsChange={setRows}
/>;
```

</details>

Identify each cell by its column `field` and stable `rowId`, matching `getRowId`
or `row.id` by default. Numeric and string IDs are distinct. Errors stay with
their rows when reordered or virtualised. Errors for missing cells, checkbox
cells or action cells are ignored. Read-only text and dropdown columns can show
errors.

The optional `message` describes the error to assistive technology for both the
cell and its editor. Messages for the same cell are combined in array order.
Omit `message` to show only the error state. Use the optional `code` to identify
errors in your application; Data Grid does not display or interpret it.

Replace the `errors` array when errors change. Editing a cell does not clear its
errors automatically. Omit `errors` or pass an empty array to clear all errors.

Use the grid's `aria-describedby` for general guidance rather than the full
error summary. Make summary links call `gridRef.current?.focusCell(rowId, field)`
or `gridRef.current?.editCell(rowId, field)` to focus the relevant cell or editor.

`onRowsChange` reports local changes, not successful validation or saving. Use
your application's validation rules or schema library to check rows before saving.
