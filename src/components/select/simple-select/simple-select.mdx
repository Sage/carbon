## Quick Start

```javascript
import {
  Select,
  Option,
  ActionOption,
  OptionGroupHeader,
} from "carbon-react/lib/components/select";
```

`Select` is controlled: pass the selected `value` and update it from `onChange`. Typeahead emits an unconfirmed change as it moves
to a matching option; pointer and keyboard selection emit a change with `selectionConfirmed: true`. Use this flag when an operation
should run only after explicit confirmation.

Build the list from `Option` children, use `OptionGroupHeader` to create labelled sections, and use `ActionOption` for an action that
does not change the selected value. Give dynamically-generated options stable React keys so their identity and accessible IDs remain
stable when the list changes. Supply an explicit `id` only when an integration requires a stable DOM ID.

### Infinite scroll example

The `isLoading` prop in combination with the `onListScrollBottom` prop can be used to implement infinite scroll.
The callback is invoked whenever the open list is scrolled to its bottom. Guard against starting duplicate requests while a request
is already in progress. The example also demonstrates using the forwarded input ref to restore focus after loading completes.

### Virtual scrolling

The `enableVirtualScroll` prop can be used to enable "virtual scrolling" to only render a few options into the DOM at any one time.
This allows an unlimited amount of children to be passed with little impact on rendering performance.

By default this will render 5 not-currently-visible options into the DOM on either side of the currently-visible ones - this value can
be customised if desired using the `virtualScrollOverscan` prop. Higher values will make scrolling smoother but may negatively impact performance.

### Selection confirmed

Arrow, Home, End, Page Up and Page Down move the active option without changing the controlled value. Confirming an option with
Enter, Space, Tab or a pointer emits `onChange` with `selectionConfirmed: true`. Typeahead changes emit
`selectionConfirmed: false`, which allows consumers to distinguish matching from an explicit confirmation.

### Dynamically adding options, and the importance of the `key` property

Provide stable keys when dynamically adding or reordering `Option` children. The component uses the
[aria-activedescendant attribute](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Attributes/aria-activedescendant)
to expose the active option to assistive technologies. Stable React keys allow each rendered option to retain that identity as the
list changes. An explicit `id` can also be supplied when a stable DOM ID is required by an integration.

### Adding an option from a dialog

`ActionOption` accepts the same props and renders the same option element as `Option`, with a distinct action treatment. Its `onClick`

## Keyboard interaction

- Enter, Space, Arrow Up, Arrow Down, Home and End open a closed Select.
- Arrow keys move through enabled options. Navigation loops by default; set `disableNavigationLoop` to stop at the ends.
- Home and End move to the first and last enabled options. Page Up and Page Down move by ten options.
- Enter or Space confirms the active option and returns focus to the input.
- Tab confirms an active option and allows focus to continue to the next control. If nothing is active, it closes without selecting.
- Escape closes the list and restores focus to the input.
- Printable characters perform typeahead selection using each Option's `text` value.

Typeahead selects the next option whose `text` starts with the buffered sequence. The `typeaheadTimeout` prop controls how long the
component waits between characters before starting a new sequence and defaults to `1500` milliseconds. Use the `text` prop even when
an Option has custom children: it supplies both the selected display text and typeahead value.

## Testing

For testing interactions with `SimpleSelect` as part of a broader user journey, we recommend testing within a browser environment using tools like Playwright or Cypress, rather than Node-based environments like JSDOM. Since JSDOM does not render visual content, mocking will be required to ensure the component's internal layout calculations function correctly, making your tests less effective.

### JSDOM tests (if required)

If you need to test within JSDOM, we provide a utility function for setting up any required global mocks:

```javascript
import { setupSelectMocks } from "carbon-react/lib/components/select";

describe("Select tests", () => {
  beforeAll(() => {
    setupSelectMocks();
  });

  test("should render", () => {
    // your test code here
  });
});
```
